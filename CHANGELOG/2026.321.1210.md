### Why each piece exists

**The suite section.** The repo was declared only under a version-specific `ubuntu-24.04:` block, so a
26.04 image matched no section at all — no repo, no package. My first attempt rewrote that block in place,
which would have declared a 24.04 section serving the 26.04 suite and broken every 24.04 consumer. The
versioned key has to be **added**.

**The bed.** The previous rounds' proof was an ad-hoc box under `/tmp`, kept out of the diff — which the
review rightly refused as a disposable target. It now ships one.

**The check.** The suite-test box's plan `include:`s the candy's plan rather than restating it. ADE
wants a box to have a plan; R2 forbids spelling one predicate twice; `include:` satisfies both.

**`tailscaled-unit-enabled` ran `systemctl is-enabled tailscaled.service` at build scope, where
no init exists, so it exited **127** and made `check box` permanently red for this candy — the first run of
the new bed failed there, not on the suite. The candy's own `run:` step already tolerates that absence with
`|| true`; the check asserting its result did not. It now asserts what the build CAN prove (the unit file
exists, which is what the enable step acts on) and leaves "enabled" to a deploy-scope check.

**The `.gitignore`.** A `git add -A` swept 22 files of `.build/`/`.check/` artifacts into the first version of
this commit. Caught before the push, undone, and replaced with the ignores this repo was missing.
